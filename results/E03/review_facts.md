# E03 review facts (items the code alone does not give)
Code facts (formulas, generator, cheater bins, CEM, recalibration blocks) are in `rules.py`, `sim.py` (lines 29-46 constants and conditions, 63-89 world, 92-107 cheater, 120-131 hand-coded cheats, 134-156 CEM, 159-196 run), `sim_recal.py` (34-52 distortions and fits, 75-85 blocks) and `real_recal.py`; verified points: claims and probabilities are fixed before outcomes (selection uses only c, topic bin and Gumbel noise; r depends only on c), honest volumes are log-uniform 10 to 500 (`sim.py:74`), and in main c equals P(y=1 | a, sigma) up to the 32-node quadrature.
- **Why EB-BRIER is exactly 100.0 with zero variance across seeds.** `rules._mom` sets tau^2 = max(var(per-source means) - mean(s2w/n), 1e-12) and kappa = s2w/tau^2, shrinking by (n m + kappa mu)/(n + kappa). Brier kappa is large (median 1,114; tau^2 at the floor in 38.5% of the original 200 worlds, `sim_eb_constants.json`; 40% of 600 worlds in the review run). The learned cheater floods about 300 claims (median policy 316 in main, `review_x1_policies.csv`), so n/(n+kappa) is large for it and small for honest sources, and its better-than-mean Brier from cherry-picking is then shrunk much less than theirs. It beats every honest source in all 600 worlds, at the floor and above it, and with the Paule-Mandel estimator too (`review_x3_eb_floor.csv`). Hence 100.0 and no seed variance (percentile saturates at the maximum).
- **EB0-IG and the variance estimator.** EB0-IG = n m/(n + kappa) is not invariant to kappa in general (it interpolates between mean IG at kappa = 0 and IG-SUM as kappa grows). Empirically it changes little with Paule-Mandel in main and R1 (11.3 vs 11.6; 20.2 vs 19.9) but R2 moves 46.1 to 39.8 (`review_x1_rules_summary.csv`).
- **Why gemma-4-31b-it has one IG run.** In pair 1 the held-out pool-B call returned an invalid claim set twice (fewer than 10 valid unique claims; one retry allowed), logged "B invalid 1 gemma-4-31b-it IG" in `llm_pundit_stdout.txt`. Per-run values: `llm_pundit_log.csv`, rows with `stage == B_heldout` (19 rows). Held-out target-rule percentiles: ACC runs 98.5, 98.5, 98.2, 99.8; BRIER 99.5, 98.5, 99.0, 99.0; IG 1.0 (31b, pair 0), 1.0 and 0.0 (26b); IG-SUM 3.0, 7.5 (31b), 10.0, 0.5 (26b); BSS 16.0, 9.0 (31b), 5.5, 24.5 (26b).
- **deepseek-v4-flash failure.** Model id `deepseek-v4-flash` via `epi.llm` with `max_tokens=4000`, reasoning effort "low" (auto for deepseek): the response had `output_tokens = 4000`, `truncated = True`, empty text (the reasoning consumed the whole budget). Dropped for gemma-4-26b-a4b-it.
- **Why the Table A4 random-split CI used 5 of 20 splits.** `real.py:162` bootstraps `range(0, a.splits, 4)`, a compute shortcut chosen for the 500-resample bootstrap, not a statistical choice. `real_v3.py` recomputes it over all 20 splits (`real_v3_stability.csv`); the intervals are similar or slightly narrower.
- **0.031 vs 0.032.** Isotonic mean baseline error is 0.031 in the main condition and 0.032 in R2 (and R2tail); logistic 0.012 in both main and R2 (`sim_recal_summary.csv`).
- **Manifold orientation and fills.** ACC is trade-direction oriented (`real.py` `score()` overrides `acc` with bet side == outcome); BRIER, LOG, IG, BSS use the post-bet price p_after as the stated r (not thresholded). `is_limit` is recorded (5.75% of first-buy claims) but not used to filter; each bet record is one fill, the first fill per user and market is the claim (`real.py:72-86`).
- **Block definition on Manifold** (`real_recal.py:20-37`): quartiles of claim time (equal claim counts, 42,175 per block); fit set for block q = claims in markets whose last ledger claim precedes the block start (81 / 261 / 469 markets, 19,103 / 64,116 / 112,340 claims for q = 1, 2, 3, weighted per claim; blocks 0-indexed, expanding window); look-ahead check in `review_manifold_lookahead.json` (up to 9% of block-3 fit markets resolved after the block start). Real-data metrics: stability and signature use the 1,855 users with >= 20 first-buy claims (83,298 claims); the recalibration backtest uses eligible blocks 1-3 (126,526 claims, 1,394 users with >= 20 eligible claims).
